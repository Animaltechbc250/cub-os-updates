# Cub OS beta updates

Public distribution channel for approved Cub beta application updates. Development source is maintained separately and stays private.

On a provisioned, owner-approved beta console, choose **Cub Control Center → Updates & alerts → Check for Cub updates & alerts**. The app checks the fixed channel in the background, downloads a newer package, verifies the pinned Cub publisher signature and installs it. The result appears in the app. No GitHub account is required.

The signed package is [beta/channel.json](beta/channel.json). Its sequence identifies a newer release; file dates are not used. The initial packages deliberately change no system files and test the complete download/verification/installation-receipt path.

The pilot updater replaces only its reviewed Cub application file list. It does not update the kernel/firmware, run package scripts, alter GPU settings, reset onboarding, copy personal data or reboot. Application file changes have per-file baseline checks, backups and interrupted-write recovery. This is not full OS-image rollback.

Installation IDs and owner approval remain local to each console; no machine identifiers or credentials are published here. A fresh installation must receive the updater, pinned public key, a newly generated identity and local owner approval before it can accept beta updates. Never copy a development machine's identity or private signing key into an image.

Only the owner publishes signed packages. Treat source archives generated by GitHub as repository source, not as OS installers.
